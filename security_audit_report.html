3. Detailed Findings & Technical Guidance

SEC-01: Plaintext Password Storage in Local SQLite & Supabase Cloud High Severity
File: org.cspdaily.report.data.User.java (Line 134) & SupabaseClient.java

Technical Finding: User credentials are saved directly as plain text in the SQLite app_user table (cv.put("password", user.password.trim())) and compared via plain string equality during online and offline authentication.

Risk & Impact: If an unauthorized party gains access to the device file system (via physical extraction, rooting, or malicious app sandbox breakout), plaintext passwords can be read immediately without brute-force difficulty.

// Remediation: Hash passwords using PBKDF2WithHmacSHA256 before persistence public static String hashPassword(String plainPassword, byte[] salt) { KeySpec spec = new PBEKeySpec(plainPassword.toCharArray(), salt, 65536, 256); SecretKeyFactory factory = SecretKeyFactory.getInstance("PBKDF2WithHmacSHA256"); return Base64.encodeToString(factory.generateSecret(spec).getEncoded(), Base64.NO_WRAP); }
Actionable Guidance: Replace raw password persistence with PBKDF2 or BCrypt salted hashing. Store password_hash and a unique per-user password_salt in app_user.
SEC-02: ADB Application Backup Flag Enabled in Manifest Medium Severity
File: AndroidManifest.xml (Line 45)

Technical Finding: The application manifest explicitly declares android:allowBackup="true" without custom backup filtering rules.

Risk & Impact: On unlocked devices with Developer Options / USB Debugging turned on, an attacker or external tool can execute adb backup org.cspdaily.report to extract internal databases and configuration files.

<!-- Remediation: Explicitly disable application backup in AndroidManifest.xml --> <application android:name=".Core" android:allowBackup="false" android:theme="@style/Theme.Csp">
Actionable Guidance: Set android:allowBackup="false" in AndroidManifest.xml to block ADB extraction of app databases.
SEC-03: Hardcoded Initial SuperAdmin Fallback Password Medium Severity
File: org.cspdaily.report.data.Auth.java (Line 24)

Technical Finding: When initializing an empty offline database, ensureDefaultSuperAdmin() seeds a default account with username admin and password admin123.

Risk & Impact: If the administrator never updates the password on a newly deployed device, standard default credentials could allow unauthorized administrative access.

Actionable Guidance: Detect if the active admin password matches the initial default ("admin123") upon login and present a mandatory password change modal.
SEC-04: Supabase Row-Level Security (RLS) Permissive Anon Policies Low Severity
File: org.cspdaily.report.data.SupabaseClient.java (Lines 1068–1121)

Technical Finding: Generated PostgREST SQL configuration applies FOR ALL TO anon USING (true) WITH CHECK (true) to allow immediate sync with the publishable key.

Risk & Impact: Any party possessing the project URL and publishable key can execute arbitrary SELECT and INSERT requests against cloud tables.

Actionable Guidance: In enterprise production environments, restrict RLS policies to authenticated JWT tokens issued by Supabase Auth rather than public anon access.

4. Verified Architectural & Platform Strengths

SEC-05: Strict SQLite Parameterized Queries (100% Parameterized) Secure · Verified

All database lookups across Day.java, Csp.java, User.java, Params.java, and SupervisorMap.java use parameterized arguments (rawQuery("... WHERE col = ?", new String[]{val})). Zero raw string concatenation occurs with user inputs, completely mitigating SQL injection threats.

SEC-06: Zero WebView / 100% Pure Native View Framework Secure · Verified

The entire user interface is constructed using pure Android native widgets (LinearLayout, TextView, EditText, Canvas). No WebView, addJavascriptInterface, or web engines exist, eliminating Cross-Site Scripting (XSS) and remote web-runtime injection surfaces entirely.

SEC-07: Robust 10-Minute Inactivity & Background Minimization Watchdog Secure · Verified

SessionManager.java actively tracks user interactions and foreground/background transitions. When the application is idle for 10 minutes or minimized in background, it locks the session and requires biometric fingerprint or password authentication to unlock.

SEC-08: Secure ContentProvider & Broadcast Receiver Configurations Secure · Verified

ApkFileProvider is configured with android:exported="false" and android:grantUriPermissions="true" for safe APK sharing with Android PackageInstaller. ReminderReceiver is bound exclusively to protected system broadcasts.
